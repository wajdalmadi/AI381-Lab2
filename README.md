
# AI381 Lab 2 — Container and CI

[![Lab 2 CI](https://github.com/wajdalmadi/AI381-Lab2/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/wajdalmadi/AI381-Lab2/actions/workflows/ci.yml)

## Project Overview

This project implements an end-to-end MLOps workflow for customer churn prediction using Python, scikit-learn, FastAPI, Docker, GitHub Actions, Trivy, and GitHub Container Registry (GHCR).

The workflow includes model training, API testing, containerization, security scanning, and automated image publishing.

## Run the Service with One Command

Run the published Docker image:

```bash

```

The API will be available at:

- http://localhost:8000/health
- http://localhost:8000/docs

## API Endpoints

### GET /health

Checks whether the API is running.

Example response:

```json
{
  "status": "ok"
}
```

### POST /predict

Accepts customer information and returns a churn probability.

Example request:

```json
{
  "tenure_months": 12,
  "monthly_fee": 75.0,
  "contract": "month-to-month",
  "internet_service": "fiber",
  "support_calls": 2
}
```

Example response format:

```json
{
  "churn_probability": 0.5
}
```

The probability shown above is illustrative; the actual value is generated by the trained model.

## Model Training

To train the model locally:

```bash
python src/train/train.py
```

This creates `model.joblib`, which is loaded by the FastAPI application.

## Automated Tests

The project includes five pytest tests covering:

1. API contract
2. Model loading
3. Input schema validation
4. Edge-case handling
5. Deterministic predictions

Run the tests locally after training:

```bash
python -m pytest tests/ -v
```

## Docker

The Dockerfile uses a multi-stage build with a Python 3.14.2 slim base image, a non-root application user, and a HEALTHCHECK.

The container exposes port 8000.

## CI/CD Pipeline

GitHub Actions runs the following workflow:

**On pull requests to main:**
- Install dependencies
- Run Ruff lint checks
- Train the model
- Run pytest tests

**On pushes to main:**
- Run lint and tests
- Build the Docker image
- Scan the image using Trivy for HIGH and CRITICAL vulnerabilities
- Publish the image to GHCR with the full commit SHA as its tag

Third-party GitHub Actions are pinned to full commit SHAs.

## Reflection

During development, the Trivy security scan initially failed because of a tool installation issue. Running Trivy through a Docker container resolved that installation problem.

A later security scan identified vulnerabilities in the container image. Updating Debian packages in the runtime stage resolved the findings reported by the configured scan.

This project demonstrates the importance of automated testing, reproducible container builds, security checks, and CI/CD in MLOps.
